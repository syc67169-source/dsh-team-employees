# 插件稳定性修复记录

2026-10-04。适用于 0.4.1。已有本地 link 安装继续加载同一源码目录。

## 已修复

1. 同进程临时文件冲突、跨进程读改写丢更新：唯一临时路径、原子 rename、目录锁覆盖条目完整操作、员工花名册、回采、权重和日志追加。脚本与制作计划也原子写入。
2. 旧版本覆盖：saveItem 在持锁期间比较磁盘 revision 和 expect；成本写入也增加 revision，防止被旧内容对象覆盖。
3. 重复 ID：串行分配自动序号，显式重复 ID 拒绝覆盖。
4. 历史队列误筛：先按 ID 取最新记录再筛 stage。索引写入时压缩为最新摘要，审计事件留在每条内容目录中。
5. 发布与回采：发布包保持 queued，实际发布由人工署名并提供链接/记录编号后确认；确认后才允许对应平台回采。支持多平台准备、保存全部目标，验证指标是非负整数。
6. 人工入口：办公室和员工设置页可查看脚本及制作文件、审核通过/拒绝、确认发布。接口复用宿主认证，拒绝无自定义请求头、错误来源或认证服务缺失的请求。
7. 成本归因：删除全局账本差额自动记到条目的逻辑。费用只称为已关联记录，0 不代表免费；遥测不再使已完成业务操作失败。
8. 模型设置：核对安装版本的模型选择由会话管理，花名册字段实际没有应用模型选择。界面、工具和文档改为“模型备注”，不再声称填 provider/model 会切换员工模型。
9. 冗余读取：一次读取条目及账本后派生办公室和流水线，删除 200 条截断；日志从尾部按块读取，复用输出 schema。
10. 请求稳定性：15 秒超时，卸载/重载中止请求；上次请求完成后才排下次轮询；无效 JSON 显示错误。

## 实际边界

- 这是文件级锁与版本检查，不是跨多个文件的数据库事务，也不保证突然断电时所有事件/摘要一同提交。
- 锁不会按时间自动抢占，以免误删另一进程新取得的锁。进程异常退出后可能遗留 `<file>.lock`；先关闭所有使用该数据目录的写入进程，再核对 owner.json 的 PID 已退出并移除该锁。未完成的临时文件不覆盖正式 JSON。
- 宿主认证/来源校验防止非授权浏览器操作，但不隔离已有本机文件/终端权限的代理。
- 员工花名册、agent preset、固定部门仍有不同职责；新增员工不会自动生成 preset，界面继续明确提示缺工牌及配置方式。
- 员工独立模型路由和媒体渲染器尚未实现。模型须在会话中选择；content_render 只是计划，不能当成真实成片。
- 旧费用记录保留，未证明归因正确；未验证真实模型费用、外部平台发布或长期多会话负载。
